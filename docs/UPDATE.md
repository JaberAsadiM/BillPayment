# سیستم به‌روزرسانی خودکار — راهنمای انتشار نسخه روی GitHub

برنامه نسخه جدید را از **GitHub Releases** بررسی می‌کند و در صورت وجود نسخه جدیدتر، آن را دانلود و مستقیماً روی دستگاه نصب می‌کند.

## نحوه کار (از سمت برنامه)

1. هنگام شروع برنامه (۳ ثانیه بعد از باز شدن) و همچنین هنگام باز شدن صفحه «تنظیمات»، برنامه آخرین Release مخزن را از GitHub API می‌گیرد (`releases/latest`).
2. اگر نسخه Release جدیدتر از نسخه نصب‌شده باشد:
   - هنگام شروع: پیام «به‌روزرسانی جدید» نمایش داده می‌شود و با تأیید کاربر به صفحه تنظیمات می‌رود.
   - در تنظیمات: کارت «🔄 به‌روزرسانی برنامه» نسخه نصب‌شده، آخرین نسخه منتشرشده، توضیحات انتشار و دکمه «دانلود و نصب نسخه جدید» را نشان می‌دهد.
3. پس از دانلود (با نوار پیشرفت)، نصاب اندروید باز می‌شود و نصب انجام می‌گیرد.
   - در اندروید ۸ به بالا، اگر برنامه اجازه «نصب برنامه‌های ناشناس» نداشته باشد، دکمه دانلود اول صفحه تنظیمات مجوز را باز می‌کند.

## قواعدی که باید رعایت شود

| مورد | قانون |
|---|---|
| **تگ Release** | باید `v` + شماره نسخه باشد: `v1.2.0` (برنامه `v` ابتدای تگ را حذف و نسخه‌ها را مقایسه می‌کند) |
| **فایل APK** | یک فایل با پسوند `.apk` به‌عنوان Asset آپلود شود (اگر چند APK باشد، بزرگ‌ترین انتخاب می‌شود) |
| **امضا** | APK باید با همان `release.keystore` قبلی امضا شود؛ در غیر این صورت اندروید اجازه نصب روی نسخه قبلی را نمی‌دهد |
| **VersionCode** | باید همیشه **بیشتر** از نسخه قبل باشد (اسکریپت آن را خودکار محاسبه می‌کند: `major*10000 + minor*100 + patch`) |
| **Release کامل** | Release باید «Published» باشد — نسخه‌های **Draft** و **Pre-release** توسط برنامه دیده نمی‌شوند |

## انتشار نسخه جدید (روش ساده — پیشنهادی)

```powershell
# در PowerShell از ریشه مخزن؛ gh CLI باید نصب و لاگین باشد (winget install GitHub.cli و gh auth login)
.\scripts\publish-update.ps1 -Version 1.1.1 -Notes "رفع مشکل جستجوی قبض و بهبود چاپ رسید"
```

این اسکریپت خودکار: نسخه را در `csproj` افزایش می‌دهد ← بیلد Release امضاشده می‌گیرد ← Release را با تگ `v1.1.1` می‌سازد و APK را آپلود می‌کند.

اگر gh CLI ندارید، به‌جای آن یک **Personal Access Token** (دسترسی `repo` برای مخزن خصوصی، یا `public_repo` برای عمومی) بدهید:

```powershell
.\scripts\publish-update.ps1 -Version 1.1.1 -Notes "..." -Token ghp_xxxxxxxxxxxx
```

## انتشار دستی (بدون اسکریپت)

1. در `src/Amard.App/Amard.App.csproj` نسخه را افزایش دهید:
   - `<ApplicationDisplayVersion>1.1.1</ApplicationDisplayVersion>`
   - `<ApplicationVersion>10111</ApplicationVersion>` (باید از قبل بزرگ‌تر باشد)
2. بیلد بگیرید: `dotnet publish src/Amard.App/Amard.App.csproj -c Release -f net10.0-android`
3. APK خروجی: `src/Amard.App/bin/Release/net10.0-android/publish/com.amard.billpayment.apk`
4. در GitHub مخزن: **Releases → Draft a new release** → تگ `v1.1.1` → عنوان و توضیحات → فایل APK را درگ کنید → **Publish release**

## نکات و عیب‌یابی

- **«هیچ نسخه‌ای منتشر نشده»**: هنوز هیچ Release published وجود ندارد — اولین Release را بسازید.
- **«rate limit»**: GitHub برای درخواست‌های بدون توکن محدودیت ۶۰ درخواست در ساعت دارد؛ در صفحه تنظیمات برنامه می‌توانید یک توکن اختیاری وارد کنید (یا مخزن را عمومی نگه دارید).
- **خطای «برنامه نصب نشد» هنگام نصب**: یا امضای APK با keystore قبلی فرق دارد، یا `ApplicationVersion` بزرگ‌تر نشده است.
- **مخزن خصوصی**: توکن باید در تنظیمات برنامه ذخیره شود (فیلد توکن GitHub در تنظیمات به‌روزرسانی).
- **تنظیمات مخزن**: اگر مخزن را تغییر دادید، نام مالک/مخزن در صفحه تنظیمات قابل ویرایش است.
- **انتشار در Google Play**: مجوز `REQUEST_INSTALL_PACKAGES` در Play مجاز نیست؛ این سیستم فقط برای توزیع مستقیم (sideload) است.
